### Changed

- **The reference queries read their ancestors and subtrees in batches.** `reference.findRefsPointingTo` with a `containerTagName` reads the containers of all its referrers in one ancestor walk (was one walk per referrer); `reference.getProvenance` reads the anchors of all source-file references in one walk (was one per reference); the data following a logical node are read from one subtree read and one ancestor walk over their roots, a uuid or a path they name looked up once per call (was two walks and one lookup per data); the logical node of a uuid climbs all its candidates in one walk. Each walk reads one level at a time, each ancestor once. The answers are unchanged: the same records, containers and anchors, in the same order, also inside a transaction.
