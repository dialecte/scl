### Added

- **The commit follows a move.** An element moved with `tx.move` (core) keeps its uuid and its lineage; at the commit, from one read of the document for all the moves of the transaction: the paths of the moved subtrees and of the references naming them are written again (`pathName`, a terminal's level names), and a path reference waiting for the place an element moves to gets its uuid; a reference named from its own place (a process resource, a variant, a behaviour's input or output) whose target the move puts out of its reach is unbound as on a delete of its target, cleared when it holds content of its own, else deleted; a terminal left naming a node its substation (or line) may not name is removed; an element of the extension namespace moved under an element of the default one is wrapped in a `Private` as on create; a container the move leaves holding nothing goes as after a delete. A moved subtree holding what references name by its place, which a move does not follow yet (a logical node, a logical device, an access point, a control block, a data instance, a data set, an input, a GOOSE or sampled value address moved to another connection, a served access point; an LNode or a connected access point moves as it is), refuses the commit: `MOVE_NOT_FOLLOWED` (`SCL4003`, `meta: { moved, parent }`).
