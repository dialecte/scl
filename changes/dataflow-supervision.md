### Added

- Every dataflow tells the supervision of its control block in the subscriber IED: `implementation.supervision` gives the LGOS (GOOSE) or LSVS (sampled values) logical node of the IED holding the ExtRef, with its `GoCBRef` / `SvCBRef` data object, its `setSrcRef` and the value naming the control block. A value names the control block by the logical device's `ldName` (`<ldName>/LLN0.<name>`), by its default name (`<IED name><inst>/LLN0.<name>`, also beside an `ldName`), relative inside its own IED (`@<inst>/LLN0.<name>`) or by its uuid (`#UID<uuid>`); the first supervising logical node in document order wins, logical nodes of an access point without server included. It is read once per call, three store reads whatever the number of dataflows, none for a document without LGOS / LSVS.
- `dataflow.supervisionsOf({ requests })`, on the query and on a transaction: the same supervision for each control block and subscriber IED asked, in the order asked, read once per call; on a transaction, from its staged state.
- Behaviour notes for adopters: the supervision follows the control block the dataflow resolved, not the ExtRef's `srcCBName` / `srcLDInst` / `srcLNClass` / `serviceType`. An ExtRef naming its control block by uuid only is supervised, and the control block's own kind (GOOSE or sampled values) decides the supervising class when the ExtRef's `serviceType` says otherwise.
