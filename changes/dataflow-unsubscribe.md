### Added

- `tx.dataflow.unsubscribe({ extRefs, withCompanions? })` ends the subscriptions of `ExtRef`s, with the `ExtRef`s implementing the same data object signal unless `withCompanions: false`. An `ExtRef` holding an internal address is kept, its binding cleared; one holding none is removed; a `SourceRef` linked to a kept one is unlinked. Once no `ExtRef` of a subscriber uses a control block, its registrations go: every `IEDName` naming that IED on a GOOSE / sampled value control block, each `ClientLN` naming where an ending `ExtRef` sits on a report control block (a client with no `ExtRef` stays); and the subscriber's LGOS / LSVS `setSrcRef` value naming the control block is cleared. While some still use it, a `ClientLN` naming a logical node they left goes, and an `IEDName` naming only a logical device or logical node they left goes, or one is cleared to the IED when a remaining `ExtRef` is registered nowhere else. A `ClientLN` of a buffered report control block, or one followed by a client that stays in an indexed one, is kept and listed in `kept`. An IED whose engineering right is `fix` is never written: the call is refused with `DATAFLOW_UNSUBSCRIBE_REFUSED` (`SCL3002`) when it holds a given `ExtRef`, and a publisher's registrations are kept.
- `query.dataflow.companionsOf({ extRef })`: the other `ExtRef`s implementing the same data object signal (same logical node, publisher logical node, data object and control block, linked to no other signal).
- Types `UnsubscribeParams`, `UnsubscribeResult`, `UnsubscribeRefusalMeta`, `RegistrationOperation`, `KeptRegistration`, `KeptRegistrationReason`, `CompanionsOfParams`.

### Changed

- Clearing an input's source clears its `serviceType` too (a bound input's service is set with its binding, not in a template): when the delete cascade unbinds an `ExtRef` that keeps its internal address, when an IED update or reconcile clears an input whose source data goes, and in `unsubscribe`. On an IED update from a template, a bound input's `serviceType` is now the project's, kept against the template and listed as kept (`data-flow`) like its source.
