### Added

- **`info.search` finds elements by their title, with the path to reveal them.** `doc.query.info.search({ term, tagNames })` answers the elements of the tags given whose title (the one `info.ofEach` gives, `compact` by default, `mode: 'full'` on request) holds the term, trimmed and case aside, each as `{ tagName, id, title, ancestorIds }`: `ancestorIds` are the ids of its ancestors from the root down, itself and the transparent `Private` left out, so a tree that loads lazily can open the path to a hit it has not read. `omit` leaves out the elements of some tags and everything below them; `limit` keeps the first hits, in the order of the tags given. Inside a transaction the staged state is searched. Reads: one per tag, the titles in one batch as `ofEach`, then one ancestor read per level of the deepest hit, whatever the number of hits; an empty term reads nothing.
